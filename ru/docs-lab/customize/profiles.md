# Профили

> Выберите, какие процессы устанавливать и в какой форме: навыки, команды или и то и другое.

Профиль задаёт, какие процессы OpenSpec ([навыки и команды](../start/setup.md#the-workflow-files-skills-and-commands) в вашем инструменте ИИ) устанавливаются на вашем компьютере. По умолчанию используется профиль `core`. При включении или исключении процессов выбранный набор сохраняется как профиль `custom`.

## Базовый набор

Профиль `core` устанавливает шесть процессов, охватывающих весь цикл от идеи до архива:

| Процесс | Назначение |
|---|---|
| [`explore`](../reference/skills.md#openspec-explore) | Продумать идею, прежде чем она станет предложением об изменении |
| [`propose`](../reference/skills.md#openspec-propose) | Создать предложение об изменении и сгенерировать все его артефакты планирования за один шаг |
| [`apply`](../reference/skills.md#openspec-apply-change) | Выполнить задачи предложения об изменении |
| [`update`](../reference/skills.md#openspec-update-change) | Скорректировать существующие артефакты планирования предложения об изменении |
| [`sync`](../reference/skills.md#openspec-sync-specs) | Перенести обновления спецификаций из предложения об изменении в `specs/`, не архивируя его |
| [`archive`](../reference/skills.md#openspec-archive-change) | Переместить завершённое предложение об изменении в архив |

Каждая ссылка ведёт к полному контракту процесса: какие аргументы он принимает, что создаёт и что возвращает в ответ.

## Расширение набора: дополнительные процессы

Помимо базового набора доступны ещё шесть процессов. Три из них (`new`, `continue`, `ff`) создают предложение об изменении по одному артефакту, а не все сразу, как `propose`.

| Процесс | Назначение |
|---|---|
| [`new`](../reference/skills.md#openspec-new-change) | Начать предложение об изменении с пустого каркаса |
| [`continue`](../reference/skills.md#openspec-continue-change) | Создать следующий артефакт планирования в предложении об изменении, по одному за раз |
| [`ff`](../reference/skills.md#openspec-ff-change) | Создать предложение об изменении и все артефакты планирования, необходимые для реализации, за один проход |
| [`verify`](../reference/skills.md#openspec-verify-change) | Проверить, что реализация соответствует артефактам предложения об изменении |
| [`bulk-archive`](../reference/skills.md#openspec-bulk-archive-change) | Архивировать несколько предложений об изменении одновременно |
| [`onboard`](../reference/skills.md#openspec-onboard) | Изучить процесс, выполнив одно реальное предложение об изменении от начала до конца |

Чтобы изменить набор, запустите интерактивное меню выбора:

```bash
openspec config profile
```

Сначала меню спрашивает, что настроить ([способ установки](#delivery-skills-commands-or-both), процессы или и то и другое), а затем показывает все двенадцать процессов в виде флажков с отметками на установленных. Любой выбор, который не совпадает в точности с шестью базовыми процессами, сохраняется как профиль `custom`, поэтому можно также снять отметки с неиспользуемых базовых процессов.

## Способ установки: навыки, команды или и то и другое

Способ установки — параметр профиля, позволяющий устанавливать только навыки или только команды. По умолчанию используется значение `both`. Раздел [Настройка проекта](../start/setup.md#the-workflow-files-skills-and-commands) описывает эти две формы и объясняет, зачем нужны обе. Точный контракт поля приведён в разделе [Параметры CLI (config.json)](../reference/configuration/config-json.md#delivery).

Изменить его можно двумя способами:

**Интерактивно**: запустите `openspec config profile` и выберите «Delivery only». Пример переключения на установку только навыков:

```
Current profile settings
  Delivery: both

? What do you want to configure? Delivery only
? Delivery mode (how workflows are installed): Skills only

Config changes:
  delivery: both -> skills
? Apply changes to this project now? (Y/n) y
```

**Напрямую**: одна команда, без интерактивных запросов:

```bash
openspec config set delivery skills   # or: both, commands
```

Способ установки никогда не изменяет имя профиля. `core` и `custom` описывают только набор процессов, а при возврате к `core` настройка способа установки сохраняется.

## Переключение профилей

Переключение состоит из двух шагов: сначала измените профиль на компьютере, затем обновите каждый проект, чтобы применить его.

1. Измените профиль:

   ```bash
   openspec config profile        # interactive
   openspec config profile core   # reset to the core six (keeps delivery)
   ```

2. Запустите обновление в каждом проекте, с которым работаете:

   ```bash
   openspec update
   ```

Если текущий каталог — это существующий проект OpenSpec, интерактивный процесс предложит выполнить в нём шаг 2.
