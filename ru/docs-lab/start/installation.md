# Установка

> Установите CLI `openspec` на свой компьютер, обновите или удалите его.


## Установка

В macOS или Linux выполните в терминале:

```bash
curl -fsSL https://openspec.dev/cli/install.sh | sh
```

В Windows выполните в PowerShell:

```powershell
irm https://openspec.dev/cli/install.ps1 | iex
```

Если установщик выведет строку `export PATH=...`, выполните её. Затем [проверьте работоспособность](#check-it-worked).

## Установка с помощью ИИ-ассистента

Вставьте это в чат с вашим ИИ:

```text
Fetch https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/install.md and follow it.
```

Или передайте файл в CLI-агент через пайп в терминале (на примере Claude Code):

```bash
curl -fsSL https://raw.githubusercontent.com/Fission-AI/OpenSpec/main/install.md | claude
```

Эта команда загружает [install.md из корня репозитория](https://github.com/Fission-AI/OpenSpec/blob/main/install.md) — промпт, написанный для любого агента, умеющего выполнять shell-команды (некоторые интеграции для IDE этого не умеют). Ваш ассистент выполнит следующие действия:

1. Пропустит установку, если CLI уже есть на вашем компьютере, и предложит обновить его тем же способом, каким он был установлен. Если использовался npm или Homebrew, ассистент один раз упомянет без навязывания, что `openspec install` переключает на автономную установку. В противном случае он покажет команду установки, приведённую выше, и дождётся вашего подтверждения перед запуском.
2. Использует npm, только если вы сами об этом попросите или если установщик завершится ошибкой, и остановится, если версия Node старше 22.12.0.
3. Проверит, что `openspec` доступен в вашем PATH.
4. Назовёт целевую папку проекта, предложит ИИ-инструмент, в котором вы сейчас общаетесь, спросит, какими ещё инструментами вы пользуетесь, а затем запустит там `openspec init` (шаг [настройки проекта](setup.md)).
5. Сообщит, какие файлы создала инициализация и как именно вызывать OpenSpec в вашем инструменте.

Ассистент останавливается перед любыми действиями, требующими повышенных привилегий, и никогда не редактирует конфигурационные файлы вашей оболочки. [Команда установки выше](#install) и [пакетные менеджеры ниже](#package-managers) являются источником истины, а промпт просто запускает их за вас.

Этот метод установки новый, и его результаты могут различаться в зависимости от используемой модели. Применяйте его, только если вы готовы исправлять возможные ошибки ИИ. В противном случае рекомендуем следовать стандартному методу ниже.

## Пакетные менеджеры

Эти менеджеры устанавливают OpenSpec как пакет Node.js, поэтому им требуется Node.js 22.12.0 или новее (Homebrew и Nix устанавливают собственную копию). Проверьте версию в терминале:

```bash
node --version
```

Если команда выводит `v22.12.0` или выше, установите пакет через npm:

```npm
npm install -g @fission-ai/openspec@latest
```

Если версия ниже, установите более новый Node с сайта [nodejs.org](https://nodejs.org), через менеджер версий (nvm, fnm, asdf, volta) или используйте [автономную установку](#install).

### Homebrew

Homebrew устанавливает OpenSpec вместе с зависимостью Node.js в macOS или Linux. В терминале:

```bash
brew install openspec
```

Формула опубликована в [homebrew-core](https://formulae.brew.sh/formula/openspec), поэтому добавлять сторонний tap не нужно.

### Yarn

Команда `yarn global add` доступна только в Yarn Classic (1.x). В современном Yarn глобальная установка удалена, поэтому используйте npm, pnpm или bun. Глобальный CLI не обязан совпадать с пакетным менеджером вашего проекта.

### Bun

Bun устанавливает OpenSpec, но не исполняет его сам, поэтому на компьютере всё равно должен быть установлен Node (см. [Пакетные менеджеры](#package-managers)). Без него любая команда завершится ошибкой `env: node: No such file or directory`. Bun обрабатывает таким образом [любой CLI на базе Node](https://bun.com/docs/pm/bunx#shebangs).

### Deno

Deno устанавливает CLI из npm и требует явного указания флагов разрешений. В терминале:

```bash
deno install --global \
  --allow-read --allow-write --allow-env --allow-sys=cpus,homedir --allow-net=edge.openspec.dev \
  npm:@fission-ai/openspec@latest
```

Некоторые команды запускают внешние программы: например, [`openspec config edit`](../reference/cli.md) открывает ваш редактор. Deno прерывает такие вызовы промптом на разрешение при каждом запуске. Чтобы отключить эти запросы, добавьте ограниченный флаг `--allow-run=<program>` в команду установки.

> [!NOTE]
> Если Deno не может разрешить тег `@latest`, укажите вместо него диапазон версий: `npm:@fission-ai/openspec@^1.7.0`.

### Nix

Репозиторий OpenSpec содержит Nix flake. Установите его в свой профиль в терминале:

```bash
nix profile install github:Fission-AI/OpenSpec
```

Или сначала запустите разовую команду без установки:

```bash
nix run github:Fission-AI/OpenSpec -- --version
```

При этом в ваш PATH ничего не добавляется, поэтому проверять установку после запуска не нужно.

Чтобы добавить OpenSpec в dev-оболочку проекта, подключите flake как вход (input) и используйте его пакет по умолчанию; список выходов приведён в [flake.nix](https://github.com/Fission-AI/OpenSpec/blob/main/flake.nix).

Пакет Nix включает скрипты автодополнения для Bash, Fish и Zsh в стандартных каталогах
(`share/bash-completion/completions`, `share/fish/vendor_completions.d`,
`share/zsh/site-functions`), поэтому они загружаются вместе с пакетом, и запускать
`openspec completion install` не требуется.

## Проверка работоспособности

Независимо от выбранного способа установки выполните в терминале:

```bash
openspec --version
```

Если выводится номер версии, значит CLI находится в вашем PATH. Установка выполняется один раз на компьютер.

Далее перейдите к [настройке проекта](setup.md). Если ваш ассистент уже запустил инициализацию, на этой странице описано, какие файлы были созданы и как их настроить.

## Параметры установки

Чтобы выбрать версию или папку, задайте переменную перед `sh`:

```bash
curl -fsSL https://openspec.dev/cli/install.sh | OPENSPEC_VERSION=v1.15.0 sh
```

- **`OPENSPEC_VERSION`**: устанавливаемый релиз, например `v1.15.0`. По умолчанию используется самый новый релиз.
- **`OPENSPEC_INSTALL_DIR`**: папка для установки. По умолчанию — `~/.local/bin` (в Windows: `%LOCALAPPDATA%\Programs\openspec`).

В Windows сначала задайте переменную:

```powershell
$env:OPENSPEC_VERSION = 'v1.15.0'
irm https://openspec.dev/cli/install.ps1 | iex
```

В Alpine Linux перед установкой выполните `apk add libstdc++ libgcc`.

### Скачивание вручную

Каждый релиз содержит по одному файлу для каждого типа компьютера:

| Компьютер | Файл |
|---|---|
| Mac, Apple silicon | `openspec-darwin-arm64.tar.gz` |
| Mac, Intel | `openspec-darwin-x64.tar.gz` |
| Linux, arm64 | `openspec-linux-arm64.tar.gz` |
| Linux, x64 | `openspec-linux-x64.tar.gz` |
| Alpine, arm64 | `openspec-linux-arm64-musl.tar.gz` |
| Alpine, x64 | `openspec-linux-x64-musl.tar.gz` |
| Windows, arm64 | `openspec-windows-arm64.zip` |
| Windows, x64 | `openspec-windows-x64.zip` |

1. **Скачайте** нужный файл со страницы [последнего релиза](https://github.com/Fission-AI/OpenSpec/releases/latest). Файлы прикрепляются через несколько минут после публикации релиза. Если вашего файла ещё нет в списке, подождите и обновите страницу или возьмите его из предыдущего релиза.
2. **Распакуйте** архив. В терминале: `tar -xzf openspec-darwin-arm64.tar.gz`. В Windows нажмите правой кнопкой мыши на файл `.zip` и выберите «Извлечь все» (Extract All).
3. **В macOS** выполните `xattr -d com.apple.quarantine openspec` в папке, куда вы распаковали архив. macOS блокирует файлы, скачанные через браузер, пока вы этого не сделаете.
4. **Переместите** `openspec` в папку из вашего PATH, например `~/.local/bin`. В Windows переместите `openspec.exe` в папку из вашего пользовательского PATH, например `%LOCALAPPDATA%\Programs\openspec`.

### Проверка скачанного файла

Чтобы убедиться, что файл был собран процессом релиза OpenSpec, выполните эту команду с помощью [GitHub CLI](https://cli.github.com):

```bash
gh attestation verify openspec-darwin-arm64.tar.gz --repo Fission-AI/OpenSpec
```

Команда завершится ошибкой, если файл был собран не этим процессом. Команда установки уже проверяет каждое скачивание по `SHA256SUMS` релиза, поэтому этот шаг необязателен.

## Переход с npm на автономную установку

Переход необязателен — версия из npm продолжает работать. Ваши настройки и проекты сохранятся; изменится только сам исполняемый файл.

**1. Установите автономную копию.** В терминале:

```bash
openspec install
```

Эта команда установит автономный `openspec` и выведет команду для удаления копии из npm или Homebrew.

**2. Удалите старую копию.** Обычно она располагается раньше в вашем PATH, поэтому до удаления будет по-прежнему запускаться именно она. Выполните команду, выведенную на шаге 1, например:

```npm
npm uninstall -g @fission-ai/openspec
```

**3. Проверьте, какая копия запускается.** Откройте новый терминал:

```bash
openspec version
```

Команда должна вывести `OpenSpec <version> (standalone)`. Если вместо этого указан пакетный менеджер, значит в вашем PATH осталась другая копия: команда `which -a openspec` (в Windows: `where.exe openspec`) покажет все найденные копии — удалите лишние.

Повторная инициализация проектов не требуется. Чтобы вернуться обратно, удалите исполняемый файл и снова выполните установку через npm.

## Обновление

В терминале, внутри каждого проекта, где вы запускали инициализацию, выполните:

```bash
openspec update
```

Когда выходит новая версия CLI, команда [`openspec update`](../reference/cli.md#openspec-update) сообщает об этом и может установить её за вас; само обновление CLI требуется один раз на компьютер. Каждый запуск также обновляет сгенерированные в проекте навыки (skills) и команды, которые сами по себе автоматически не обновляются. Для актуального проекта выводится `✓ All 2 tool(s) up to date (v1.7.0)`.


> [!WARNING]
> При автономной установке выполняйте `openspec install` для замены исполняемого файла на месте; `openspec update` лишь уведомляет о выходе новой версии. В Homebrew выполните `brew upgrade openspec`. В Deno повторно запустите [команду установки Deno](#deno) с флагом `-f`, иначе установленная команда не будет перезаписана. В Nix используйте `nix profile upgrade openspec`.

> [!NOTE]
> Глобальная установка через npm привязана к конкретной установке Node. Если вы переключите версию Node с помощью nvm, команда `openspec` не перенесётся автоматически — установите её заново для новой версии Node.

## Удаление

Чтобы удалить OpenSpec, выполните приведённые ниже шаги — ни один из них не затрагивает ваш исходный код. Вы также можете указать своему агенту на этот раздел и поручить удаление ему.

**1. Удалите [автодополнение оболочки](../reference/cli.md#openspec-completion)** (если вы его настраивали), пока сам CLI ещё доступен. В терминале:

```bash
openspec completion uninstall
```

**2. Удалите CLI.** При автономной установке удалите файл `~/.local/bin/openspec` (в Windows: `%LOCALAPPDATA%\Programs\openspec`, а также уберите эту папку из пользовательского PATH). При установке через npm выполните в терминале:

```npm
npm uninstall -g @fission-ai/openspec
```

В Homebrew: `brew uninstall openspec`. В Deno: `deno uninstall --global openspec`. В Nix: `nix profile remove openspec`. После этого ваша оболочка больше не должна находить команду `openspec`.

**3. Удалите оставшиеся файлы или сохраните их.**

- Сгенерированные файлы агентов: навыки `openspec-*` и команды `opsx` в каталогах вроде `.claude/` или `.agents/` внутри каждого проекта. Пути для каждого инструмента перечислены на странице [Поддерживаемые инструменты](../reference/supported-tools.md); MiniMax Code хранит навыки в `~/.minimax/skills`.
- Остатки от старых версий: маркерные блоки в `CLAUDE.md` или `AGENTS.md` (удалите сам блок, оставив файл) и промпты `opsx-*.md` в `~/.codex/prompts`.
- Папка `openspec/`: не спешите с удалением. Каталоги `specs/` и `changes/archive/` представляют собой историю вашей системы в виде обычных файлов Markdown, которые отлично читаются и без OpenSpec.
- Состояние на уровне компьютера: настройки и идентификатор телеметрии в `~/.config/openspec/`; переопределения схем, регистрации хранилищ и встроенные схемы автономной установки (`binary-schemas/`) в `~/.local/share/openspec/` (в Windows: `%APPDATA%\openspec`, `%LOCALAPPDATA%\openspec`). Регистрации представляют собой просто указатели — сами репозитории хранилищ, на которые они ссылаются, остаются нетронутыми.
