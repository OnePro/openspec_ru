# Design: layer-1-ru

## Context

Готовы и заархивированы: трекинг апстрима (манифест 80 записей, drift-инструменты, CI) и LLM-пайплайн (`translate.mjs` fresh/delta, `validate-translation.mjs`, `build-ru.mjs` с гейтом `pnpm build` + `generate:skills` → `dist-ru/`). Переведено 3 файла (README, installation.md, new-change.ts). Известные факты реализации: Kimi-endpoint работает через flavor `anthropic`; глоссарий-линт требует маскировки keep-терминов; отклонённые черновики складываются в `.cache/rejected/`.

Обнаруженный пробел: `seed-manifest.mjs` покрыл 0 файлов зоны `schemas` — паттерны матчат только `*.md`, а `schemas/` содержит `schema.yaml` + 4 markdown-шаблона.

## Goals / Non-Goals

**Goals:**

- 100% файлов зон `templates` (19) и `schemas` (5) переведены, валидны, сборка overlay зелёная.
- `dist-ru/` содержит skills + slash-команды топ-5 инструментов, пререндеренные генераторами самого апстрима.
- `npx openspec-ru apply` делает EN-проект русским за один запуск, идемпотентно.

**Non-Goals:**

- Перевод docs-lab/сайта (change 4), CLI runtime-строк, старого `docs/`.
- Публикация в npm registry — бета-дистрибуция через `npx github:OnePro/openspec_ru`; публикация — отдельное решение.
- Поддержка всех 30+ инструментов — топ-5, остальные с предупреждением.
- Автоматический reviewed-статус переводов.

## Decisions

### D1: Расширение seed под не-markdown зоны

`seed-manifest.mjs` получает таблицу зон с glob-паттернами: `templates` → `src/core/templates/**/*.ts`, `schemas` → `schemas/**/*.{yaml,yml,md}`, и т.д. Повторный seed идемпотентен: существующие записи (со статусами и sha) не трогаются, добавляются только новые EN-пути.

### D2: Валидатор учит YAML по тем же принципам, что TS

Для `schema.yaml` проверяется равенство структуры ключей (множество путей ключей) между EN и RU; значения-идентификаторы (имена артефактов, `id`, пути шаблонов) не переводятся — белый список непереводимых ключей. Текстовые значения (инструкции, описания) переводятся и проходят глоссарий-линт.

### D3: Пререндер команд генераторами апстрима, а не ручными шаблонами

build-ru после `pnpm build` вызывает command-generation адаптеры из собранного RU-dist для топ-5 инструментов и складывает результаты в `dist-ru/commands/<tool>/`. Мы не воспроизводим форматы 5 инструментов руками — апстрим сам знает, как выглядит команда для Cursor или Copilot; при изменении формата в новой версии апстрима наш бандл наследует изменение автоматически. **Альтернатива** (ручные шаблоны на инструмент) отвергнута: 5 параллельных форматов, которые надо отслеживать вручную.

### D4: Патчер детектирует по артефактам, а не по каталогам

Наличие `.claude/` не значит, что OpenSpec для Claude Code установлен; наличие `.claude/skills/openspec-explore/SKILL.md` — значит. Патчер сканирует известные раскладки топ-5 (таблица: инструмент → skillsDir, commandsDir, паттерны файлов) и работает только с совпавшими. Перезапись — только файлов, чьи имена матчат OpenSpec-паттерны (`openspec-*`, `opsx*`); всё прочее в тех же каталогах не трогается. Блок AGENTS.md/CLAUDE.md между маркерами `<!-- OPENSPEC:START/END -->` заменяется на RU-версию из бандла, если маркеры найдены.

### D5: Идемпотентность через сравнение содержимого

Патчер сравнивает текущее содержимое целевого файла с RU-версией из бандла: совпадает — «актуально», отличается — перезапись. Это одновременно даёт идемпотентность и восстановление после `openspec update`. Версия бандла (= тег из upstream.json) печатается в отчёте.

### D6: Дистрибуция беты — прямо из GitHub

Пакет живёт в этом репо (`tools/apply/` с собственным `package.json`, бандл в `dist-ru/` коммитится в репо). Установка беты: `npx github:OnePro/openspec_ru apply`. Публикация в npm откладывается до вычитки переводов (статусы `reviewed`).

## Risks / Trade-offs

- [Kimi местами игнорирует глоссарий при массовом переводе] → ретрай-цикл + карантин `.cache/rejected/`; после прогона — ручной разбор карантина (известная стоимость, измерена на README).
- [Перевод 18 TS-файлов (~40k слов) — длительная операция с риском таймаута] → перевод батчами по 2–4 файла за запуск с промежуточными коммитами; состояние в манифесте, прогон возобновляем.
- [Адаптеры команд апстрима не экспортируют публичный API] → fallback: вызов `openspec init` из RU-собранного dist в scratch-проект для каждого инструмента с последующим сбором файлов (медленнее, но всегда работает).
- [Патчер перезапишет что-то лишнее в чужом проекте] → строгие паттерны имён + dry-run флаг `--dry-run` со списком изменений без записи.
- [Версия OpenSpec у пользователя новее пина] → предупреждение о расхождении версий (spec: «Проверка совместимости»), но не отказ — patch всё равно применим, риск на пользователе.

## Migration Plan

Не требуется: все артефакты новые, затрагивается только этот репозиторий и (по явной команде пользователя) его проекты.

## Open Questions

- Точные пути раскладки команд для топ-5 инструментов — выясняются из `src/core/config.ts` и адаптеров апстрима при реализации (известно, что реестр там есть; задача 3.1).
- Имя npm-пакета при будущей публикации (`openspec-ru` vs `@openspec-ru/*`) — отложено до решения о публикации.
