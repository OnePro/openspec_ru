# Proposal: translation-pipeline

## Why

Переводческая поверхность MVP — порядка 85–90 тыс. слов (templates, schemas, docs-lab, README, строки сайта). Вручную это недели работы, а при апстрим-дрейфе — постоянная рутина. Нужен LLM-пайплайн, который переводит файлы целиком с соблюдением единой терминологии и стиля, переносит апстрим-дельты в существующие переводы и гарантирует техническую корректность результата (markdown-структура, интерполяции, идентификаторы) без ручной проверки каждого файла.

## What Changes

- `glossary.md` — нормативный словарь терминов OpenSpec (EN → RU) с запретными вариантами; единственный источник терминологии для всех переводов.
- `style-guide.md` — правила русского технического стиля (обращение, времёна, оформление кода, кавычки, числа) для переводов.
- `tools/translate.mjs` — LLM-раннер с двумя режимами: `fresh` (EN → RU с нуля) и `delta` (EN_old + diff + RU_old → RU_new); на вход подаётся глоссарий, стайлгайд и правила зоны из манифеста; после успешной валидации обновляет манифест (статус `machine`, base_blob_sha).
- `tools/validate-translation.mjs` — детерминированный валидатор: для markdown — равенство числа код-блоков, структуры заголовков, ссылок/якорей, неизменность frontmatter-ключей; для TS-шаблонов — равенство множества `${...}`-токенов, имён констант/импортов/экспортов, прохождение `pnpm build` после overlay; для всех файлов — глоссарий-линт (запрещённые EN-термины в русском тексте, обязательные соответствия) и непереводимость идентификаторов (`/opsx:*`, `name:` в frontmatter, маркеры `<!-- OPENSPEC:... -->`).
- Сборочный шаг `tools/build-ru.mjs`: overlay `ru/**` поверх исходников апстрима на пинned-теге и `pnpm build` как финальная проверка слоя templates (использует тестовый стенд апстрима).

## Capabilities

### New Capabilities

- `translation-glossary`: управление нормативной терминологией и стилем перевода — глоссарий и стайлгайд как версионируемые артефакты, линт переводов на соответствие им.
- `llm-translation-pipeline`: LLM-перевод файлов в режимах fresh и delta с учётом глоссария/стиля, детерминированная валидация результата по типу файла, обновление манифеста после успешного перевода.

## Impact

- **Новые файлы**: `glossary.md`, `style-guide.md`, `tools/translate.mjs`, `tools/validate-translation.mjs`, `tools/build-ru.mjs`, тесты валидатора.
- **Зависимости**: доступ к LLM API (провайдер настраивается, по умолчанию — через переменные окружения); Node.js 20+; для `build-ru` — pnpm и клон исходников апстрима на пинned-теге (кэшируемый, только для сборки).
- **Связи**: использует `manifest.json`, `upstream.json` и дрейф-инструменты из change `bootstrap-ru-translation` (должен быть завершён первым).
- **Не затрагивается**: сам перевод контента — отдельные change'и (слой templates+schemas, затем docs-lab + сайт); пайплайн лишь инструмент для них.
