# Дизайн

## Контекст

См. proposal.md — зачем. Работа выполнена после консультации advisor'а (оценка рисков лендинга, структура страницы шагов, согласованность редиректов). Факты, определившие решения, проверены в коде патчера (`tools/apply/cli.mjs`): `openspec-ru init` блокируется без `.git`, сам выполняет `openspec init` интерактивно и накатывает RU-бандл; установщик OpenSpec поддерживает пин `OPENSPEC_VERSION`.

## Цели / нецели

**Цели:**

- Первый экран сайта — openspec-ru с понятным дисклеймером неофициальности.
- Страница установки, по которой последовательность выполняется без догадок: предусловия, команды, проверки после каждого шага, разбор ошибок.
- Согласованность версий: сайт, README и команды ссылаются на один тег `#v1.15.0`.

**Нецели:**

- Изменение апстримового контента (перевод остаётся faithful).
- Маркетинговая целевая страница (отдельный репозиторий у апстрима; у нас — обзор внутри документации).
- Редиректы 308 (advisor: сначала 302, постоянные — после наблюдения).

## Решения

### D1: Лендинг — обзор openspec-ru, а не документация OpenSpec

`/` и `/docs` → `/docs/ru`. Принято по цели продвижения перевода; риск путаницы (посетитель искал OpenSpec, а видит сторонний пакет) смягчён дисклеймером «неофициальный проект» на первом экране и ссылкой на обычную документацию. Реализация: патч `public/_redirects` (приоритет Cloudflare) + meta-refresh fallback в оверлейных `page.tsx`; порядок секций — RU-конфиг публикации.

### D2: Одна страница установки вместо пары quickstart/install

Advisor: два похожих документа расходятся. Шаги 0–3 на одной странице `/docs/ru/install`: предусловия (git + Node.js 20.19+), установка CLI с пином версии и проверкой `openspec --version`, `npx …#v1.15.0 init`, проверка результата (`openspec/config.yaml`, skills), сценарии `update`/`apply` и разбор ошибок ниже.

### D3: siteUrl сайта — собственный домен

`ru/website-strings/lib/shared.ts`: дефолт `https://openspec-ru.pages.dev` вместо апстримового `openspec.dev`. Иначе sitemap/canonical/OG вели бы поисковиков и соцсети на чужой домен.

### D4: Пин версий в README по сайту

README приведён к тому же тегу `#v1.15.0`, что и команды на сайте (`@latest`/`#HEAD` убраны). Расхождение создавало бы конфликт версий после выхода апстрима 1.16.

## Риски / компромиссы

- [Посетитель путает openspec-ru с официальным продуктом] → дисклеймер на первом экране и ссылка на обычную документацию; риск принят осознанно по цели продвижения.
- [Апстрим вернёт страницу-обзор `/docs`] → Cloudflare-правило `/docs → /docs/ru` останется приоритетным; при обновлении апстрима пересмотреть правило и fallback осознанно (зафиксировано в проекте сайта).
- [Команды не прогнаны на чистых системах] → взяты из проверенной переведённой документации; ручной прогон Windows/macOS оставлен открытым.
