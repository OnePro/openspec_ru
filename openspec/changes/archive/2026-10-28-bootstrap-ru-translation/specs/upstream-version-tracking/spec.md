# Spec Delta

## Purpose

Привязывает перевод к конкретной версии апстрима (Fission-AI/OpenSpec) и позволяет в любой момент быстро определить, какие переведённые файлы устарели, и получить дельту оригинала для их обновления.

## ADDED Requirements

### Requirement: Привязка к версии апстрима

Система SHALL хранить привязку к версии апстрима в файле `upstream.json` в корне репозитория: имя репозитория, тег релиза и commit sha. Инструменты MUST использовать только эту привязку при обращении к апстриму.

#### Scenario: Чтение привязки

- **WHEN** любой инструмент запрашивает версию апстрима
- **THEN** он получает репозиторий, тег и commit sha из `upstream.json` и не обращается к другим источникам версии

#### Scenario: Обнаружение перезаписи тега

- **WHEN** drift-check обнаруживает, что тег из `upstream.json` указывает на commit, отличный от записанного
- **THEN** инструмент завершается с явной ошибкой, сообщающей о рассинхронизации тега

### Requirement: Манифест переводимых файлов

Система SHALL хранить манифест (`manifest.json`) со записями о каждом переводимом файле: путь EN-файла в апстриме, путь RU-файла в репозитории, base_blob_sha (blob sha EN-файла в момент перевода), статус (`pending`, `machine`, `reviewed`) и зона (`templates`, `schemas`, `docs-lab`, `website`, `meta`).

#### Scenario: Регистрация переведённого файла

- **WHEN** файл переведён и добавлен в дерево `ru/`
- **THEN** в манифесте существует запись с его EN-путём, RU-путём, актуальным base_blob_sha и статусом

#### Scenario: Симметричная сверка манифеста и файловой системы

- **WHEN** запущен drift-check
- **THEN** он сообщает об ошибке для каждой записи манифеста, чей RU-файл отсутствует на диске, и для каждого файла в `ru/`, не имеющего записи в манифесте

### Requirement: Обнаружение дрейфа перевода

Система SHALL предоставлять команду drift-check, которая для каждой записи манифеста сверяет текущий blob sha EN-файла на пинned-теге апстрима с base_blob_sha и формирует отчёт, разделяющий файлы на «актуальные», «изменённые», «удалённые в апстриме» и «новые в апстриме без перевода». Сверка MUST выполняться через GitHub API без клонирования репозитория апстрима.

#### Scenario: Файл изменился в апстриме

- **WHEN** blob sha EN-файла на пинned-теге отличается от base_blob_sha в манифесте
- **THEN** drift-check помечает файл как «изменённый», сохраняет latest_blob_sha и включает его в отчёт

#### Scenario: Новый файл в отслеживаемой зоне апстрима

- **WHEN** на пинned-теге в зонах `docs-lab/`, `src/core/templates/`, `schemas/` существует файл, отсутствующий в манифесте
- **THEN** drift-check включает его в отчёт как «новый без перевода»

#### Scenario: Все файлы актуальны

- **WHEN** все blob sha совпадают с base_blob_sha и новых файлов нет
- **THEN** drift-check завершается успешно с отчётом «дрейф отсутствует»

### Requirement: Дельта оригинала для устаревшего файла

Система SHALL предоставлять команду drift-diff, которая для указанного устаревшего файла выводит diff между EN-версией на момент перевода (base_blob_sha) и текущей EN-версией (latest_blob_sha), чтобы переводчик переносил только изменения.

#### Scenario: Получение дельты

- **WHEN** вызвана drift-diff для файла, помеченного «изменённым»
- **THEN** выводится unified diff старой и новой версий EN-файла

#### Scenario: Запрос дельты для актуального файла

- **WHEN** вызвана drift-diff для файла без дрейфа
- **THEN** инструмент сообщает, что файл актуален, и не выводит diff

### Requirement: Обновление base_blob_sha после переперевода

Система SHALL позволять зафиксировать переперевод файла: поднять base_blob_sha записи манифеста до latest_blob_sha, сняв пометку «изменённый».

#### Scenario: Фиксация переперевода

- **WHEN** перевод устаревшего файла обновлён и подтверждён
- **THEN** base_blob_sha в манифесте устанавливается равным latest_blob_sha, и файл перестаёт считаться устаревшим

### Requirement: Уведомление о новом релизе апстрима

Система SHALL периодически (по расписанию в CI) проверять появление тегов апстрима новее пинned-версии и создавать уведомление (GitHub issue) со списком новых тегов и сводкой дрейфа.

#### Scenario: Вышел новый релиз

- **WHEN** в апстриме появился тег новее пинned-тега
- **THEN** CI создаёт или обновляет issue с номером новой версии и предложением поднять привязку

#### Scenario: Новых релизов нет

- **WHEN** новых тегов нет
- **THEN** CI завершается без создания issue
