# Дизайн

## Контекст

См. proposal.md — зачем. Есть два готовых слоя перевода: `ru/website-strings/` (17 файлов UI-строк, все `reviewed`, манифест следит за дрейфом относительно апстрива) и `ru/docs-lab/` (42 файла контента, все `reviewed`). Для CLI слоя проект уже использует модель «клон апстрива на пине + оверлей `ru/**` + сборка» (`tools/build-ru.mjs`). Сайт апстрива — Next.js/Fumadocs: контент генерируется из `docs-lab/**/*.md` скриптом `website/scripts/sync-docs.mjs` на `prebuild`, публикуемые страницы и лейблы секций заданы в `website/docs.sync.config.mjs`, сайт собирается статически (`output: 'export'` в `next.config.mjs`).

Изученные факты (файлы оверлея `ru/website-strings/`):
- `app/layout.tsx`: переводчик уже поставил `<html lang="ru">`, но шрифт `Inter({ subsets: ['latin'] })` — кириллица упрётся в fallback.
- `lib/remark-faq.ts`: `slugify` режет `[^a-z0-9 -]` — кириллический заголовок FAQ даёт пустой id.
- `app/api/search/route.ts`: orama `language: 'english'` — русские запросы не найдут русский текст.
- Лейблы сайдбара живут вне оверлея — в `website/docs.sync.config.mjs` (секции Start/Customize/Multi-repo (beta)/Reference).

## Цели / нецели

**Цели:**

- Один командой собрать полностью русский статический сайт из имеющихся слоёв.
- Обновление апстрива = поднять пин + перестроить; оверлеи и патчи накладываются тем же порядком.
- Сборка Next.js — обязательный гейт: сломанный оверлей не доходит до `dist-website/`.

**Нецели:**

- Хостинг, домен, CI/CD-публикация, браузерные smoke-проверки — шаг 4.
- Двуязычность, hreflang — архитектура standalone-RU, решение принято.
- Перевод лейблов, которых нет в `docs.sync.config.mjs` (вкладки навигации формируются из секций автоматически).

## Решения

### D1: Та же модель «пин + оверлей», что у CLI

`tools/build-website-ru.mjs` повторяет форму `build-ru.mjs`: кэшированный клон `Fission-AI/OpenSpec` на коммите из `upstream.json` → копия `website/` в рабочее дерево `.cache/website-ru/site` → наложение файлов `ru/website-strings/**` (только существующие в манифесте пары) → наложение `website-ru-patches/**` → копия `ru/docs-lab/**` в `docs-lab/` рабочего дерева → `pnpm install && pnpm build` в дереве → результат в `dist-website/`.

**Альтернатива** — редактировать вендоренный форк `website/` напрямую: отвергнута. Ломает путь обновления апстрива (ручной мерж) и обесценивает манифест с дрейф-трекингом оверлея строк.

### D2: Патчи i18n — полнофайловый оверлей второго слоя

Глубокие модификации (три файла оверлея строк) правятся прямо в `ru/website-strings/` — они и есть полные копии файлов, манифест продолжает их трекать. Конфиг сайдбара (`docs.sync.config.mjs`) не входит в манифест → отдельный слой `website-ru-patches/`: файл копируется из апстрива с переведёнными только лейблами секций (`label`), список страниц, slug и `source` неизменны.

### D3: Три точечные русские правки в оверлее строк

- `app/layout.tsx`: `subsets: ['latin', 'cyrillic']`.
- `lib/remark-faq.ts`: slugify сохраняет кириллицу (`а-яё` и `А-ЯЁ` через toLowerCase), поведение для латиницы не меняется.
- `app/api/search/route.ts`: `language: 'russian'` (поддерживается orama, см. ссылку в комментарии файла).

Каждая правка — минимальный дифф; дрейф-дельты от апстрима продолжают переноситься режимом delta.

### D4: Контент подкладывается под штатный sync-docs

`ru/docs-lab/**` копируется в `docs-lab/` рабочего дерева до сборки; штатный `prebuild` (`sync-docs.mjs`) генерирует `content/docs` по тому же манифасту публикации. Отдельный генератор не пишем — меньше кода, меньше расхождений с апстримом.

## Риски / компромиссы

- [Тяжёлая сборка: pnpm install тянет зависимости сайта] → кэширование дерева между прогонами; гейт запускается явно, а не на каждый тест.
- [Якоря русских заголовков меняются относительно EN] → известное ограничение standalone-перевода; проверка ссылок/якорей — часть шага 4, на сборку не влияет (slugify теперь даёт непустые id).
- [pnpm может отсутствовать у контрибьютора] → сборка сайта — опциональная задача контрибьютора; ошибка сборки объясняет требование.
