# Design: translation-pipeline

## Context

См. proposal.md — Why. Опирается на артефакты change `bootstrap-ru-translation`: `manifest.json` (пути, base_blob_sha, статусы, зоны), `upstream.json` (пин на тег), drift-инструменты (источник дельт для режима delta). Известные характеристики исходников: в TS-шаблонах 112 интерполяций `${...}` (константные вставки), в docs-lab — сотни код-блоков; апстрим предоставляет `pnpm build` и parity-тесты skills как бесплатный QA-стенд.

## Goals / Non-Goals

**Goals:**

- Перевод файла целиком одним LLM-вызовом с глоссарием и стайлгайдом в контексте.
- Дешёвое обновление перевода при дрейфе: переносится дельта, а не перепереводится файл.
- Ни один файл не попадает в `ru/` и манифест, не пройдя детерминированную валидацию.
- Формальная гарантия для слоя templates: сборка апстрима после overlay.

**Non-Goals:**

- CAT/TMS-инфраструктура (translation memory, сегментация) — файлы переводятся целиком.
- Автоматический reviewed-статус: `machine → reviewed` проставляет только человек.
- Перевод CLI runtime-строк и старого `docs/` — вне MVP-скоупа программы.
- Batch-UI/веб-интерфейс — только CLI.

## Decisions

### D1: Глоссарий — парсируемый markdown, не PO/gettext

`glossary.md` — markdown-таблица строгого формата (`| EN | RU | правило |`), где правило ∈ `переводить | не переводить | запрещено:<вариант>`. Инструменты парсят её напрямую; человеку она остаётся читаемой и редактируемой. PO-формат отвергнут: гранулярность по строкам ломает контекст LLM-перевода и требует внешней инфраструктуры.

### D2: Раннер переводит файл целиком, провайдер LLM сменный

`tools/translate.mjs` формирует промпт: системная роль + `glossary.md` + `style-guide.md` + правила зоны (из `area` манифеста: что не переводить в templates vs docs) + EN-контент. Файлы MVP-скоупа (до ~8k слов) помещаются в контекст целиком — сегментация не нужна и вредна для согласованности. Провайдер настраивается через env (`TRANSLATE_API_BASE`, `TRANSLATE_API_KEY`, `TRANSLATE_MODEL`); запросы — обычный chat-completions-совместимый HTTP, без SDK-локина. Температура 0 для воспроизводимости.

**Альтернатива** — построчный/сегментный перевод с TM: отвергнута, см. D1.

### D3: Валидация строго детерминированная

LLM не участвует в приёмке. Проверки по типу файла:

| Тип | Проверки |
|---|---|
| markdown | число код-блоков, последовательность уровней заголовков, множество ссылок/якорей, ключи frontmatter, идентификаторы (`/opsx:*`, `name:`) |
| TS-шаблоны | множество `${...}`-токенов, имена импортов/констант/экспортов, затем `pnpm build` после overlay (D5) |
| все | глоссарий-линт (вне код-блоков и frontmatter) |

Файл, не прошедший валидацию, отклоняется: раннер возвращает его LLM с перечнем нарушений (до N=3 попыток), затем помечает файл как требующий ручного разбора. Манифест обновляется только после успеха.

### D4: Delta-режим на тройке (EN_old, diff, RU_old)

Вход delta-перевода — EN-версия на момент перевода (blob по base_blob_sha), unified diff base→latest (от drift-diff) и текущий RU-файл. LLM переносит дельту; полный переперевод запрещён инструкцией промпта, что держит стоимость и сохраняет вычитанные места. После валидации base_blob_sha поднимается до latest.

### D5: Сборка апстрима как финальный гейт слоя templates

`tools/build-ru.mjs`: кэшированный клон апстрима на пинned-commit → копирование `ru/**` поверх → `pnpm install && pnpm build && pnpm generate:skills`. Падение сборки = отказ валидации с выводом компилятора. Побочный продукт — готовые RU-артефакты (skills/команды) в `dist-ru/` для change 3 (overlay-патчер). Тот же шаг при полной сборке станет форком CLI — переход фаз без переделки.

## Risks / Trade-offs

- [LLM тихо искажает структуру длинного файла] → валидация D3 отклоняет; ретрай с перечнем нарушений; при 3 неудачах — ручной разбор.
- [Стоимость/лимиты LLM API на ~90k слов] → delta-режим минимизирует повторные прогоны; fresh-перевод идёт пачкой по одному разу; модель настраивается (можно дешёвую для docs-lab, сильную для templates).
- [Глоссарий разъезжается с реальностью переводов] → глоссарий-линт гоняется по всему `ru/` в CI; правка глоссария без правки переводов видна сразу.
- [Апстрим изменит формат templates (не строки, а структуру TS)] → сборочный гейт D5 ловит это на этапе поднятия пина, до перевода.
- [Промпт-инъекция из текста апстрима] → контент EN-файла оборачивается в явные границы, инструкции внутри контента игнорируются; валидация D3 ограничивает blast radius структурой.

## Migration Plan

Bootstrap-change должен быть завершён первым (манифест и дрейф-инструменты — входные данные пайплайна). Порядок внедрения: glossary/style-guide → валидатор (с тестами на синтетических парах файлов) → раннер fresh → сборочный гейт → delta-режим. Откат не требуется: пайплайн пишет только в `ru/` и манифест, всё под git.

## Open Questions

- Seed-набор терминов глоссария (~40–60 терминов OpenSpec) — составляется в задаче 1.1, вычитывается мейнтейнером.
- Конкретный LLM-провайдер и модели по умолчанию — определяются при первом запуске, сменны через env без правки кода.
