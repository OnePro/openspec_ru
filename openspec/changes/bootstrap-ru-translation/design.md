# Design: bootstrap-ru-translation

## Context

Апстрим — Fission-AI/OpenSpec, текущий релиз `v1.15.0` (commit `8e0288df12d401b0e183e2f47254d22528c1dffb`). Переводческая поверхность (замерено shallow-клоном):

| Слой | Что | Объём |
|---|---|---|
| 1. AI-facing | `src/core/templates/**` (19 файлов: 15 workflows + 4 служебных; npm-пакет шипит только `dist` — skills генерируются из шаблонов), `schemas/` | ~43k слов |
| 2. Документация | `docs-lab/` (42 файла — источник сайта через `website/scripts/sync-docs.mjs`), README.md, install.md | ~42k слов |
| 3. Вебсайт | `website/` (Fumadocs/Next.js → статический экспорт) | ~1–2k слов строк |
| 4. CLI-строки | console-сообщения `src/commands` | не переводим |

Ключевые факты апстрима, определяющие дизайн:

- `openspec init` раскладывает skills/команды в проект юзера из скомпилированных шаблонов; `openspec update` перезаписывает их — поэтому overlay-патчер должен быть идемпотентным и переприменяемым.
- Корневые `skills/` генерируются из `src/core/templates` скриптом `pnpm generate:skills`; parity-тест апстрима следит за синхронностью — бесплатный QA-стенд для переведённых шаблонов.
- В TS-шаблонах 112 интерполяций `${...}` — константные вставки; их множество в RU-файле обязано совпадать с EN-файлом.
- Версии апстрима — git-теги (changesets → npm), значит привязка = пин на тег.

Стратегические решения, принятые в обсуждении (детали — в последующих change'ах):

- **Фазовая дистрибуция**: сначала overlay-патчер (`npx openspec-ru apply` перезаписывает установленные EN-артефакты русскими), затем полный форк CLI (`@openspec-ru/cli`). Переход обеспечивается тем, что переводы сразу хранятся как дерево-зеркало апстрима в `ru/`, а overlay поверх `upstream@tag` + `pnpm build` — общий шаг обеих фаз.
- **LLM-пайплайн перевода**: режимы `fresh` (EN→RU) и `delta` (EN_old + diff + RU_old → RU_new), детерминированный валидатор (код-блоки, `${...}`-токены, frontmatter, глоссарий-линт), статусы `machine → reviewed` в манифесте.
- **Сайт**: форк `website/`, sync-docs читает `ru/docs-lab`; пока только локальная сборка, деплой отложен (статика позже встанет и на Cloudflare Pages, и на VPS).
- **MVP-скоуп программы**: слои 1–3; старый `docs/` и CLI-строки не переводим; overlay — топ-5 инструментов.

## Goals / Non-Goals

**Goals:**

- Структура репозитория, в которую последующие change'и просто «кладут переводы».
- Однозначная привязка к версии апстрима (тег + commit).
- Манифест как единственный источник правды о состоянии перевода каждого файла.
- Дрейф-чек за секунды (без клона апстрима, через GitHub API) и дельта оригинала по каждому устаревшему файлу.
- CI-уведомление о новом релизе апстрима.

**Non-Goals:**

- Сам перевод любого контента (это change'и 2–4).
- `tools/translate/` (LLM-раннер) и валидатор — change 2.
- Форк `website/` и `npx openspec-ru` — change'и 3–4.
- Автоматический rebase/merge с апстримом — апстрим не вендорится, только читается по API.

## Decisions

### D1: Трекинг через манифест с blob sha, а не форк с git merge

`manifest.json` хранит на каждый файл: `en` (путь в апстриме), `ru` (путь у нас), `base_blob_sha` (git blob sha EN-файла в момент перевода), `status`, `area`. Дрейф = несовпадение текущего blob sha файла на пинned-теге с `base_blob_sha`. Дельта для переперевода = `git diff` между старым и новым blob (оба скачиваются по API).

**Почему не форк с merge**: перевод внутри файлов апстрима означает конфликты при каждом merge, невозможность отчёта «какие файлы устарели» и смешение кода с контентом. **Почему не gettext/Weblate**: контент — маркдаун и TS-литералы целиком, PO-гранулярность по строкам ломает контекст LLM-перевода и тянет инфраструктуру.

### D2: Апстрим не вендорим — читаем через GitHub API

Blob sha файла на теге получаем из `GET /repos/{owner}/{repo}/git/trees/{tag}?recursive=1`; содержимое blob — `GET /repos/{owner}/{repo}/git/blobs/{sha}`. Дрейф-чек не требует клона и работает в CI за один запрос дерева.

**Альтернатива**: git submodule на тег. Отвергнута: лишние сотни мегабайт в репо и замедление клона ради операции, которая делается двумя HTTP-запросами. Rate limit (60/час анонимно) снимается `GITHUB_TOKEN` в CI; локально одного запуска в минуты достаточно.

### D3: Статусы перевода в манифесте

`pending` → `machine` (LLM-черновик) → `reviewed` (вычитано человеком); `outdated` — производный флаг дрейф-чека, не хранится вручную. Дрейф-чек при обнаружении несовпадения sha помечает файл `outdated` и сохраняет `latest_blob_sha` — после переперевода `base_blob_sha` поднимается до `latest_blob_sha`.

### D4: Привязка на релизный тег, не на main

`upstream.json`: `{ "repo": "Fission-AI/OpenSpec", "tag": "v1.15.0", "commit": "8e0288df" }`. Обновление привязки — осознанное действие (поднять тег → прогнать drift-check → волна перепереводов), а не постоянная гонка за main.

### D5: Идентификаторы не переводятся

`/opsx:*`, `name:` в frontmatter skills, `<!-- OPENSPEC:START -->`, пути и якоря — API, которое парсит CLI. Валидатор (change 2) будет это проверять; в манифесте фиксируется зоной `area`, чтобы правила валидации различались для `templates` и `docs-lab`.

## Risks / Trade-offs

- [GitHub API rate limit при анонимном доступе] → `GITHUB_TOKEN` в CI; локально дрейф-чек — редкая операция, 60 запросов/час хватает (дерево — 1 запрос).
- [Ретег/перезапись тега апстримом] → в `upstream.json` храним и commit sha; drift-check сверяет, что тег всё ещё указывает на записанный commit, иначе явная ошибка.
- [Манифест разъедется с реальностью при ручных правках] → дрейф-чек дополнительно проверяет, что каждый `ru`-путь существует, а каждый файл в `ru/` имеет запись в манифесте (симметричная сверка).
- [Переименование файла в апстриме выглядит как delete+add] → отчёт дрейфа разделяет «изменён», «удалён в апстриме», «новый в апстриме непереведённый» (последнее — по скану зон `docs-lab`, `src/core/templates`, `schemas` на пинned-теге).

## Open Questions

- Состав seed-глоссария (`change → изменение`, `spec → спецификация`, `artifact → артефакт`, ...) — решается в change 2 до запуска LLM-перевода.
- Кто проставляет статус `reviewed` — пока предполагаем единственного мейнтейнера.
- Домен и хостинг RU-сайта — отложено осознанно; статический экспорт совместим с Cloudflare Pages и VPS+nginx.
