# Дельта спецификации

## Purpose

Предоставляет встроенный локальный веб-интерфейс (`openspec-ru start web` / `openspec-ru stop web`) для наглядного просмотра канбан-доски изменений на всех этапах жизненного цикла и чтения спецификаций репозитория в реальном времени.

## ADDED Requirements

### Requirement: Запуск и блокировка без каталога openspec

Команда `openspec-ru start web [--port <port>]` SHALL проверять наличие каталога `openspec/` в целевой папке проекта перед запуском сервера. Если каталог `openspec/` отсутствует, команда MUST завершиться с кодом `1` и понятным сообщением об ошибке, не запуская сервер и не создавая файлов.

#### Scenario: Запуск в репозитории с openspec

- **WHEN** пользователь выполняет `openspec-ru start web` в каталоге, содержащем `openspec/`
- **THEN** запускается локальный HTTP-сервер на порту `3000` (или следующем свободном порту, либо порту из `--port`) и выводится URL панели

#### Scenario: Запуск в папке без openspec

- **WHEN** пользователь выполняет `openspec-ru start web` в папке, где нет каталога `openspec/`
- **THEN** команда выводит сообщение об ошибке в `stderr`, не запускает сервер и завершается с кодом `1`

#### Scenario: Фоновый запуск флагом --detach для AI-агента

- **WHEN** агент или пользователь выполняет `openspec-ru start web --detach` в репозитории с `openspec/`
- **THEN** сервер запускается в фоновом процессе, дожидается готовности и записи файла состояния, выводит URL панели и немедленно завершает родительский процесс с кодом `0`

### Requirement: AI-скилл openspec-ui и команда /opsx:ui

Бандл `dist-ru/` и патчер `applyRuPatch` SHALL включать и устанавливать скилл `openspec-ui` и slash-команду `ui` (`/opsx:ui` / `/opsx-ui`) для всех обнаруженных поддерживаемых инструментов проекта, позволяя запускать (`start web --detach`) и останавливать (`stop web`) веб-панель голосовыми/текстовыми запросами в сессии агента («открой спеки», «открой панель со спецификациями», «закрой спеки»).

#### Scenario: Установка скилла openspec-ui патчером

- **WHEN** в проекте с инициализированным инструментом из топ-5 выполняется `openspec-ru apply` (или `init` / `update`)
- **THEN** в каталоге skills и команд этого инструмента создаются или обновляются `openspec-ui/SKILL.md` и команда `ui` (`opsx/ui.md`, `opsx-ui.md` и т.д.)

### Requirement: Остановка веб-сервера

Система SHALL поддерживать три способа корректной остановки запущенного веб-сервера: командой `openspec-ru stop web` из любого терминала, запросом из веб-интерфейса (`POST /api/shutdown`) и сигналом прерывания (`SIGINT` / `Ctrl+C`).

#### Scenario: Остановка командой stop web

- **WHEN** сервер запущен в репозитории и пользователь выполняет `openspec-ru stop web`
- **THEN** запущенный сервер этого репозитория останавливается, файл состояния процесса удаляется, а команда сообщает об успешной остановке

#### Scenario: Остановка кнопкой из браузера

- **WHEN** пользователь нажимает кнопку выключения сервера в шапке веб-интерфейса
- **THEN** браузер отправляет `POST /api/shutdown`, сервер закрывает соединения и завершает процесс с кодом `0`

### Requirement: Отображение всех этапов изменений на канбан-доске

Веб-панель SHALL отображать изменения из `openspec/changes/` по пяти этапам: «В проекте» (`draft` — изменения без `tasks.md`, включая пустые черновики с `.openspec.yaml`), «К выполнению» (`todo` — `0%` задач), «В работе» (`progress` — `1%–99%` задач), «Готово» (`done` — `100%` задач) и опционально «Архив» (`archive` из `openspec/changes/archive/`).

#### Scenario: Изменение на стадии планирования видно на доске

- **WHEN** в `openspec/changes/<name>/` существует `.openspec.yaml` или `proposal.md`, но ещё нет `tasks.md`
- **THEN** изменение отображается в колонке «В проекте» с состояниями четырёх артефактов (`complete`, `ready`, `blocked`)

#### Scenario: Отображение прогресса и деталей изменения

- **WHEN** пользователь открывает карточку изменения на доске
- **THEN** в модальном окне доступны вкладки «Предложение», «Дизайн», «Спецификации» (с переключением между несколькими `specs/<capability>/spec.md`) и «Задачи» со статусом чекбоксов

### Requirement: Чтение спецификаций проекта на всех ОС

Веб-панель SHALL сканировать и отображать все основные спецификации из `openspec/specs/**/spec.md` с нормализацией разделителей путей (`/`) на Windows, macOS и Linux, структурированным рендером секций `Purpose`, карточек `Requirement` (`R1..Rn`) и сценариев `Scenario` (`WHEN/THEN/AND` и `КОГДА/ТОГДА/И`).

#### Scenario: Открытие спецификации на Windows

- **WHEN** сервер запущен на Windows и пользователь выбирает спецификацию в разделе «Спецификации»
- **THEN** спецификация открывается без ошибки 404, отображая назначение, оглавление требований, таблицы и шаги сценариев

### Requirement: Живое автообновление в режиме только чтения

Сервер SHALL отслеживать изменения файлов внутри `openspec/` и отправлять уведомления браузеру через Server-Sent Events (`GET /api/events`), при этом сервер MUST NOT изменять или удалять файлы внутри `openspec/`.

#### Scenario: Автообновление при изменении файла агентом

- **WHEN** агент создаёт артефакт или отмечает задачу `- [x]` в `tasks.md`
- **THEN** сервер отправляет событие `update` по SSE, и веб-панель автоматически обновляет карточки и открытый документ без перезагрузки страницы
