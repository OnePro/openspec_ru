# release-versioning Specification

## Purpose
Определяет правила версионирования `openspec_ru` в привязке к версии оригинального OpenSpec (`MAJOR.MINOR.PATCH`), структуру `CHANGELOG.md` и `CONTRIBUTING.md`, а также автоматическую проверку согласованности версий перед выпуском релизных Git-тегов.

## Requirements

### Requirement: Версионирование в пределах MAJOR.MINOR апстрима

Версия `openspec_ru` (в `package.json`, `tools/apply/package.json` и Git-тегах `vX.Y.Z`) SHALL иметь те же `MAJOR.MINOR`, что и тег апстрима в `upstream.json` (например, `1.15` при апстриме `v1.15.0`), а компонент `PATCH` (`1.15.0`, `1.15.1`, … `1.15.9`) MUST использоваться для собственных релизов `openspec_ru` в рамках этой версии апстрима.

#### Scenario: Соответствие версии апстриму

- **WHEN** в `upstream.json` указан тег `v1.15.0`
- **THEN** допустимыми версиями релиза `openspec_ru` являются `1.15.0`, `1.15.1` и любые `1.15.x`

#### Scenario: Расхождение MAJOR.MINOR отклоняется

- **WHEN** в `upstream.json` указан тег `v1.15.0`, а в `package.json` выставлена версия `0.1.0` или `1.16.0`
- **THEN** проверка `release:check` завершается ошибкой несоответствия `MAJOR.MINOR`

### Requirement: Проверка совместимости версий по MAJOR.MINOR

Патчер `applyRuPatch` SHALL считать установленный CLI `openspec` совместимым с бандлом `openspec-ru`, если их `MAJOR.MINOR` совпадают (например, `openspec 1.15.0` и бандл `v1.15.2`), и MUST выводить предупреждение только при отличии `MAJOR.MINOR`.

#### Scenario: Ревизия перевода внутри 1.15 не вызывает предупреждения

- **WHEN** у пользователя установлен `openspec 1.15.0`, а версия бандла `openspec-ru` равна `v1.15.1`
- **THEN** патчер применяется без предупреждения о расхождении версий

#### Scenario: Разные минорные ветки вызывают предупреждение

- **WHEN** у пользователя установлен `openspec 1.14.3`, а версия бандла `openspec-ru` равна `v1.15.1`
- **THEN** патчер выводит предупреждение о расхождении версий

### Requirement: Правила ведения CHANGELOG.md

Репозиторий SHALL содержать корневой `CHANGELOG.md`, в котором для каждого релиза `X.Y.Z` присутствует секция `## [X.Y.Z] — YYYY-MM-DD` с указанием базового тега апстрима и группировкой изменений по рубрикам (`Добавлено`, `Изменено`, `Исправлено`, `Синхронизация с апстримом`).

#### Scenario: Проверка наличия записи в CHANGELOG.md

- **WHEN** выполняется команда `npm run release:check` для текущей версии `1.15.0`
- **THEN** скрипт проверяет наличие заголовка `## [1.15.0]` в `CHANGELOG.md` и завершается ошибкой при его отсутствии

### Requirement: Руководство для контрибьюторов CONTRIBUTING.md

Репозиторий SHALL содержать корневой `CONTRIBUTING.md`, описывающий правила изменения переводов (`ru/` → `dist-ru/`), работы с `glossary.md` и `style-guide.md`, список непереводимых элементов, обязательные проверки (`npm test`, `npm run validate:ru`, `npm run release:check`) и порядок выпуска релизных тегов `vX.Y.Z`.

#### Scenario: Наличие всех регламентных разделов в CONTRIBUTING.md

- **WHEN** контрибьютор открывает `CONTRIBUTING.md`
- **THEN** документ содержит правила перевода, правила ведения `CHANGELOG.md`, схему версионирования `MAJOR.MINOR.PATCH` и команды проверки перед PR и релизом
