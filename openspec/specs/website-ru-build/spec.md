# website-ru-build Specification

## Purpose
Сборка standalone русского сайта OpenSpec из апстрива на пине, оверлея строк `ru/website-strings`, патчей i18n и контента `ru/docs-lab`; сборка Next.js — обязательный гейт качества слоёв.

## Requirements

### Requirement: Сборка русского сайта из слоёв

Система SHALL предоставлять команду `npm run build:website:ru`, которая собирает статический сайт: клон апстрива `Fission-AI/OpenSpec` на коммите из `upstream.json`, копия `website/` в рабочее дерево, наложение файлов `ru/website-strings/**` по парам `manifest.json`, наложение `website-ru-patches/**`, копия `ru/docs-lab/**` в `docs-lab/` рабочего дерева, затем `pnpm install` и `pnpm build`. Результат SHALL помещаться в `dist-website/`. Неуспешная установка зависимостей или сборка MUST считаться отказом: `dist-website/` не считается готовым, команда завершается ненулевым кодом.

#### Scenario: Успешная сборка

- **WHEN** все слои наложены и `pnpm build` проходит
- **THEN** `dist-website/` содержит `index.html` и HTML-страницы документации с русским текстом

#### Scenario: Сломанный оверлей ломает сборку

- **WHEN** файл оверлея делает TypeScript невалидным
- **THEN** команда завершается ненулевым кодом с выводом компилятора, указывающим на файл оверлея

### Requirement: Русская i18n собранного сайта

Собранный сайт MUST быть русским: `<html lang="ru">`, шрифт с кириллическим подмножеством, slugify сохраняет кириллицу в якорях FAQ, поисковый анализатор orama — `russian`, лейблы секций сайдбара — русские.

#### Scenario: Кириллический FAQ даёт непустой якорь

- **WHEN** заголовок FAQ написан по-русски
- **THEN** сгенерированный id якоря содержит кириллические символы, а не пустую строку

#### Scenario: Русские лейблы сайдбара

- **WHEN** собран сайт и открыта документация
- **THEN** секции сайдбара отображают русские лейблы из `website-ru-patches/docs.sync.config.mjs` при том же наборе страниц и slug, что в апстриме

### Requirement: Сайт открывается обзором openspec-ru

Собранный сайт SHALL перенаправлять `/` и `/docs` на `/docs/ru` (обзор openspec-ru), а секция «OpenSpec RU» SHALL быть первой в сайдбаре. Обзорная страница MUST содержать дисклеймер, что openspec_ru — неофициальный проект, не продукт Fission-AI, и ссылку на обычную документацию OpenSpec.

#### Scenario: Первый визит

- **WHEN** посетитель открывает корень сайта
- **THEN** он попадает на обзор openspec-ru с дисклеймером неофициальности и путём к установке

#### Scenario: Сайдбар

- **WHEN** открыта любая страница документации
- **THEN** первой секцией сайдбара идёт «OpenSpec RU», за ней — секции переведённой документации OpenSpec

### Requirement: Точная последовательность установки на сайте

Сайт MUST содержать страницу установки openspec-ru с пронумерованной последовательностью: предусловия (git-репозиторий в корне проекта, Node.js 22.12.0+), установка CLI OpenSpec через `https://openspec.dev/cli/install.*` с закреплением актуальной ветки из `upstream.json` (`1.16.x`) и проверкой `openspec --version`, выполнение `npx github:OnePro/openspec_ru#v1.16.0 init` в корне проекта и проверка результата. Страница MUST описывать действия при типичных ошибках (нет git, не та версия, нет артефактов при apply).

#### Scenario: Установка без догадок

- **WHEN** пользователь выполняет шаги страницы на чистой машине
- **THEN** после шага 3 в проекте есть русские артефакты OpenSpec, а каждый шаг содержит команду проверки результата

#### Scenario: Блокировка без git

- **WHEN** пользователь без git-репозитория читает страницу до выполнения команд
- **THEN** страница заранее требует `git init` и объясняет блокировку `openspec-ru init`
